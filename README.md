## 这是什么

`互动` 是一套给 AstrBot 用的群聊互动玩法合集。装好就能用，不需要数据库、
不需要第三方库、不需要任何初始化 —— 群里第一个签到的人会自动建档。

它解决的是「群太冷清」和「群太吵」这两件事：日常轻玩法拉活跃，
圈层玩法拉留存，娱乐玩法拉话题，同时用冷却、限额和任务给刷屏踩刹车。

## 亮点

- **免 @ 触发** —— 群里直接发「签到」「/签到」「!签到」都能生效，游戏开局后也不用任何前缀
- **零第三方依赖** —— 只用 Python 标准库和 `astrbot.api.*`，不会有装不上的包
- **数据会话隔离** —— 按「平台 + 群 / 私聊」分文件，插件升级不丢数据
- **不阻塞事件循环** —— 序列化与写盘都在线程池，`fsync` + 原子替换保证不写坏文件
- **配置可视化** —— 23 个配置分组全部能在 WebUI 里可视化调整
- **数值经得起推敲** —— 抽奖、打劫、竞猜、转盘、Boss 战、宠物的期望都做过推演与守恒脚本，不存在刷分漏洞
- **可检索的标签体系** —— 22 项成就带分类与稀有度，支持关键词 / 分类 / 稀有度筛选
- **长线玩法** —— 赛季按月重置、群 Boss 战全群协作、宠物养成给每日一个理由回来
- **510 项单测 + 165 项真实框架冒烟** —— 每次改动都会跑，含免唤醒端到端回归

## 环境要求

| 项 | 要求 |
| --- | --- |
| AstrBot | `>=4.10,<5`（`metadata.yaml` 的 `astrbot_version`） |
| Python | `>=3.10`（`pyproject.toml` 的 `requires-python`） |
| 第三方依赖 | **无** |

AstrBot 侧所需的一切（`astrbot.api.*`）都由 AstrBot 自身提供，
所以插件本身**不需要 `pip install` 任何东西**。

## 快速开始

1. 把本仓库克隆/下载到 AstrBot 的 `data/plugins/` 下，目录名用
   `astrbot_plugin_hudong`：

   ```bash
   cd /path/to/astrbot/data/plugins
   git clone https://github.com/techjiang/astrbot-plugin-hd.git astrbot_plugin_hudong
   ```

   > 仓库名是 `astrbot-plugin-hd`，插件名是 `astrbot_plugin_hudong`
   > （`metadata.yaml` 的 `name`），两者不同。AstrBot 以**目录名**拼出
   > 模块路径（`data.plugins.<目录名>.main`），所以目录名建议与
   > `metadata.yaml` 的 `name` 保持一致，避免 WebUI 里显示的名字、
   > 配置文件 `<目录名>_config.json` 与别的插件混淆。
   >
   > 另外，`data/plugins/` 的父目录会被 AstrBot 加进 `sys.path`，
   > 含连字符的目录名 `astrbot-plugin-hd` 虽然能 import，
   > 但不是合法的 Python 标识符，调试、静态检查与部分工具会踩坑。
   >
   > **仓库根目录就是插件目录**，不要再套一层同名子目录。
2. 重启 AstrBot，或在 WebUI 里点「重载插件」
3. 群里发送 `/互动` 查看玩法总览

```
/签到              # 每日签到领积分
/积分              # 余额、等级、称号、统计、今日幸运数字
/每日任务          # 6 个日常任务，发「/领取」一键领奖
/抽奖              # 消耗积分抽奖，含称号与头像框
/猜数字 → /猜 50    # 猜中得积分，范围与次数可配
/接龙 互动          # 直接发中文词语即可接龙
/掷骰 3 20         # 或者直接发 3d20
/幸运数字          # 每天一个专属数字，猜中领奖
/八球 今天要加班吗   # 一句玄学答案
/排行榜 积分        # 积分/签到/抽奖/猜中/接龙/打劫/掷骰/幸运
/投票 晚饭吃啥 | 火锅 | 烧烤
```

完整玩法、参数与示例见 **[使用文档.md](./使用文档.md)**。

## 玩法一览

> **所有指令都不需要 @机器人**，群里直接发就行；`/`、`!`、`#` 前缀可有可无。
> 游戏开局后更是「直接发消息」即可参与。

### 日常与娱乐

| 分类 | 指令 | 说明 |
| --- | --- | --- |
| 日常 | `签到`、`积分`、`每日任务`、`领取` | 签到攒积分，6 个日常任务可领奖 |
| 娱乐 | `抽奖`、`猜数字` → 直接发数字、`接龙`、`掷骰`、`幸运数字`、`八球` | 抽称号、猜数、接龙、掷骰、玄学 |
| 娱乐 | `占卜`、`笑话`、`随机 火锅\|烧烤` | 每日运势、冷笑话、帮你做选择 |

### 小游戏（4 个新增）

| 指令 | 玩法 | 说明 |
| --- | --- | --- |
| `21点 [下注]` → `要牌` / `停牌` | 黑杰克 | 庄家补到 17 点，起手 21 点按 2.5 倍赔付 |
| `数字炸弹` → 直接发数字 | 拆弹 | 区间内踩中炸弹者扣分，每人安全一次加分 |
| `猜谜` → 直接发答案 | 抢答 | 内置谜题库，第一位答对者获奖 |
| `海龟汤` → `海龟汤 <问题>` / `汤底` | 情境推理 | 内置汤面与汤底，可提问也可直接揭晓 |
| `谁最先 [目标词]` → 直接发 | 手速 | 谁先发出目标词谁赢 |

### 社交（5 个新增）

| `扎心 [@某人]` | 互损文案 |

### 对局类（v1.2.0 新增 7 个）

| 指令 | 玩法 | 说明 |
| --- | --- | --- |
| `竞猜 问题 \| A \| B` → `下注 <序号> <金额>` → `开奖 [序号]` | 弹幕竞猜 | 按实时赔率派彩，冷门高赔；到点自动开奖 |
| `井字棋` → 直接发格号 | 人机对弈 | AI 会连三也会堵你，理论上打不赢 |
| `扫雷 [边长 雷数]` → 直接发格号 | 多人共建 | 踩雷扣分，清完全盘大家分奖池 |

| `抛硬币 [正\|反] [赌注]` | 猜正反 | 无参数只抛不押，带赌注才结算 |
| `决斗盘 <手势> [赌注]` | 石头剪刀布蜥蜴斯波克 | 每招恰好克两招、被两招克，完全平衡 |
| `转盘 [次数]` | 幸运大转盘 | 期望低于消耗的回收型抽奖，可连抽 |

### 成长类（v1.2.0 新增 3 个）

| 指令 | 说明 |
| --- | --- |
| `成就` | 22 项成就，达成自动解锁并发奖 |
| `转生 [确认]` | Lv.15 起可转生：积分归零换永久收益加成（最高 ×2.0） |
| `我的加成` | 查看转生加成、成就进度与今日商店折扣 |

### 标签体系（v1.3.0 新增 2 个）

把 22 项成就升级成**可检索、可筛选的标签**：每条标签都有分类（日常 / 财富 /
对局 / 社交 / 运气 / 探索）、由阈值**推导**出的稀有度（普通 / 稀有 / 史诗 / 传说）
和完成进度。

| 指令 | 说明 |
| --- | --- |
| `标签` | 收集概览 + 最接近完成的 5 条 |
| `标签 稀有` / `标签 日常` | 按稀有度或分类筛选 |
| `标签 已获得` / `标签 未获得` | 只看已解锁 / 未解锁 |
| `标签 搜索 抽奖` | 关键词搜索（成就名、成就码、分类名都能命中） |
| `标签搜索 <关键词>` | 等价写法 |

> 筛选词顺序随意：`标签 运气 稀有` 与 `标签 稀有 运气` 等价；
> 关键词会归一化，`标签 搜索 签到！` 的尾随标点不会影响命中。

### 世界线 · 赛季 · 养成（v1.3.0 新增 3 类）

前三批玩法都是「一个人的事」，这一批补上了**全群协作**与**跨天长线**。

| 指令 | 玩法 | 说明 |
| --- | --- | --- |
| `讨伐 [Boss名]` → `攻击 <积分>` → `讨伐状态` | 群 Boss 战 | 全群合力打，按实际伤害占比瓜分奖池 |
| `赛季` → `赛季 领取` | 赛季 | 按自然月重置，按「本季积分增量」定位段位并发奖 |
| `宠物` → `喂食` / `起名 <名字>` | 宠物养成 | 领养、照料、成长五个阶段，20 小时冷却 |

**Boss 战的经济模型**：奖池刻意**小于**全员满额投入（例如史莱姆王
1200 HP、奖池 700），所以合作必然有损耗 —— 打得越多亏得越多，
只能转移资产不能造分。溢出伤害（最后一下打过头）会**原额退款**，
按「实际打出的伤害」记功而不是请求值。

**赛季的设计意图**：排名依据是「本季增量」而不是总积分，避免老玩家
永久霸榜。跨月自动清零增量，但**总积分一分不动**。

**宠物为什么不做收益**：单次照料产出上限 6，期望低于签到下限（10）。
它是情绪价值和标签来源，不是刷分路径 —— 这条约束写进了测试。

### 商店 · 排行 · 工具

| 指令 | 说明 |
| --- | --- |
| `商店` → `购买 <道具名>` | 称号 / 头像框 / 消耗品；每天随机折扣 |
| `背包` → `佩戴 <称号名>` | 查看与装备 |
| `排行榜 <维度>` | 积分 / 签到 / 抽奖 / 猜中 / 接龙 / 打劫 / 掷骰 / 幸运 / 井字棋 / 扫雷通关 / 数字破解 / 竞猜 / 大转盘 / 抛硬币 / Boss 伤害 / Boss 击杀 / 本赛季积分 / 赛季奖励 |
| `投票 问题 \| 选项1 \| 选项2` → `投 <编号> <序号>` → `投票结果` | 投票 |
| `互动`（帮助）、`互动状态`、`互动统计` | 帮助与运行状态 |
| 关键词回复 | WebUI 配置关键词与回复内容 |

完整菜单随时可发 `互动` / `菜单` 查看。

## 配置

所有配置都在 AstrBot WebUI → 插件配置 里，36 个分组：

`enabled` · `currency_name` · `trigger` · `sign_in` · `lottery` ·
`guess_number` · `word_chain` · `vote` · `rank` · `rob` · `dice` ·
`blackjack` · `bomb` · `riddle` · `turtle_soup` · `rush` · `fortune` ·
`shop` · `social` · `lucky` · `eight_ball` · `roast` ·
`wager` · `tictactoe` · `mine` · `codebreaker` · `coin` · `rpsls` ·
`wheel` · `rebirth_play` · `boss` · `season` · `pet` ·
`achievements` · `auto_reply` · `permission`

默认值开箱即用。打劫与掷骰默认关闭（这两个玩法对群氛围影响较大，
由群主主动开启更合适）；其余玩法默认全开。

**触发方式**（`trigger` 分组）：

- `wake_free`：免 @ 直接触发（默认开）—— 群里不带 @ 也能用指令
- `auto_regex_games`：游戏消息自动接管（默认开）—— 猜数字/接龙/炸弹等直接发消息即可参与

**权限**（`permission` 分组）：除群聊限制与冷却外，还支持 `allow_list`
白名单、`deny_list` 黑名单与 `admin_ids` 插件管理员。

逐项说明见 [使用文档 · 配置项对照](./使用文档.md#配置项对照)。

## 数据与迁移

数据落在 AstrBot 的插件数据目录
`<AstrBot 根目录>/data/plugin_data/astrbot_plugin_hudong/<平台>_<会话>.json`，
一个群一个文件：

```json
{
  "users": { "10001": { "balance": 328, "streak": 3, "...": "..." } },
  "polls": { "a1b2c3": { "question": "晚饭吃啥", "votes": {}, "...": "..." } },
  "meta":  { "created_at": 0, "updated_at": 0 }
}
```

- 遵循 AstrBot 上架规范，放在 `data/plugin_data/<插件名>/` 下，随插件升级一起迁移
- 整目录拷走即可迁移
- 写入是「节流 3 秒 + 合并 + 卸载强制刷盘」，使用 `mkstemp` → `fsync` → `os.replace`
- 文件权限 `0640`，同组运维账号可读可备份
- 文件损坏会自动重建，不会让插件起不来

## Logo

<img src="assets/glyph-128.png" alt="互动" width="72" align="left">

仓库根目录的 `logo.png` 是 AstrBot WebUI 插件列表读取的固定文件名；
`assets/` 下还有多尺寸图标（`logo-*.png`）、纯图形版（`glyph-*.png`）、
favicon、文档横幅（`banner.png`）与社交预览图，全部由 `tools/build_logo.py`
从 `assets/design-source.png` 自动生成，可一键重建：

```bash
python tools/build_logo.py assets/design-source.png assets
```

这条命令除了写 `assets/`，还会把结果再写一份到**仓库根目录的 `logo.png`**
（AstrBot 只认这个位置）。生成是确定性的：同一份设计稿重跑不会产生 diff。

> 重建素材需要 **Pillow**，它只是开发期依赖（`astrbot` 本身就依赖它）。
> 插件运行**不需要** Pillow，`tools/` 目录也不会被打进运行路径。

生成逻辑在 `tools/logo_tools.py`，六边形轮廓由设计稿的白色描边**实测**得出
（`LEFT_SLOPE` / `RIGHT_SLOPE` 等常量），因此换设计稿只需重新实测这几个数；
配套单测见 `tests/test_logo_tools.py`（11 项，含「尖角必须保住」的回归用例）。
